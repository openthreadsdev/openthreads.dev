# OpenThreads.dev - Claude Code Instructions

## Project Overview

OpenThreads.dev is a modern web application built with React, TypeScript, and Vite. It features a blog platform with a custom design system built on shadcn/ui components.

## Tech Stack

- **Framework:** React 18 with TypeScript
- **Build Tool:** Vite with SWC
- **Styling:** TailwindCSS with custom theme
- **UI Components:** shadcn/ui (Radix UI primitives)
- **Routing:** React Router v6
- **State Management:** Redux + TanStack Query
- **Testing:** Vitest + React Testing Library
- **Icons:** Lucide React

## Project Structure

```
src/
├── articles/           # Blog article content and metadata
├── components/         # Custom React components
│   ├── ui/            # shadcn/ui components (auto-generated)
│   ├── layout/        # Layout components (Nav, Footer, etc.)
│   └── sliders/       # Carousel/slider components
├── hooks/             # Custom React hooks
├── lib/               # Utility functions and helpers
├── pages/             # Page components (route handlers)
├── redux/             # Redux store and slices
├── test/              # Test files and utilities
├── App.tsx            # Root application component
└── main.tsx           # Application entry point
```

## Code Conventions

### Import Paths

- Use `@/` alias for absolute imports from `src/` directory
- Example: `import { Button } from "@/components/ui/button"`
- Example: `import { formatDate } from "@/lib/blog"`

### Component Patterns

1. **Functional Components:** Use arrow functions with explicit types

   ```tsx
   interface ComponentProps {
     title: string;
   }

   export function Component({ title }: ComponentProps) {
     return <div>{title}</div>;
   }
   ```

2. **File Naming:**
   - Components: PascalCase (e.g., `PostCard.tsx`, `SiteNav.tsx`)
   - Utilities: camelCase (e.g., `blog.ts`, `utils.ts`)
   - Pages: PascalCase with "Page" suffix (e.g., `HomePage.tsx`, `BlogPage.tsx`)

3. **Export Pattern:**
   - Use named exports for components: `export function Component() {}`
   - Default export only for page components and App.tsx

### Styling Conventions

#### Custom Theme Colors

The project uses a custom "OpenThreads" color scheme with `ot-*` prefixes:

- `ot-bg` - Main background color
- `ot-surface` - Surface/card backgrounds
- `ot-text` - Primary text color
- `ot-muted` - Muted/secondary text
- `ot-border` - Border color
- `ot-accent` - Accent/highlight color
- `ot-accent-hover` - Accent hover state
- `ot-danger` - Error/danger state

**Always use `ot-*` colors instead of default shadcn colors for custom components.**

#### Custom Utility Classes

- `rounded-card` - Card border radius (1rem)
- `rounded-btn` - Button border radius (0.75rem)
- `card-hover` - Standard card hover effect
- `max-w-content` - Content max width (1120px)
- `max-w-prose` - Prose max width (70ch)

#### Typography

- **Sans-serif:** Inter (default)
- **Monospace:** JetBrains Mono
- Use `font-mono` for code, dates, and technical content

### Component Guidelines

#### shadcn/ui Components

- UI components in `src/components/ui/` are auto-generated by shadcn/ui CLI
- Do NOT manually edit these files unless absolutely necessary
- To add new shadcn components, use: `npx shadcn@latest add [component-name]`
- Always use these components as building blocks for custom components

#### Custom Components

- Place custom components in `src/components/` root
- Use semantic HTML elements
- Prefer composition over complexity
- Keep components focused and single-purpose

#### Page Components

- All pages are in `src/pages/` and end with `Page.tsx`
- Export as default: `export default HomePage;`
- Use React Router's hooks for navigation (`useNavigate`, `useParams`)

### State Management

1. **Local State:** Use `useState` for component-specific state
2. **Server State:** Use TanStack Query for data fetching and caching
3. **Global State:** Use Redux (configured in `src/redux/`)

### Routing

- Routes are defined in [App.tsx](src/App.tsx)
- Use `<Link>` from `react-router-dom` for internal navigation
- Route structure:
  - `/` - Home page
  - `/about` - About page
  - `/blog` - Blog listing
  - `/blog/:slug` - Individual blog post
  - `/tags/:tag` - Posts by tag
  - `/contact` - Contact page
  - `/privacy` - Privacy policy

### Testing

- Tests are in `src/test/` directory
- Use Vitest with React Testing Library
- Test file naming: `*.test.tsx` or `*.test.ts`
- Run tests: `npm run test`
- Watch mode: `npm run test:watch`

## Common Tasks

### Adding a New Page

1. Create component in `src/pages/` (e.g., `NewPage.tsx`)
2. Add route in [App.tsx](src/App.tsx) `<Routes>` section
3. Add navigation link in [SiteNav.tsx](src/components/SiteNav.tsx) if needed

### Adding a New Component

1. Create component file in `src/components/`
2. Use TypeScript interfaces for props
3. Follow existing naming and export patterns
4. Use `ot-*` colors for styling
5. Import and use shadcn/ui components as needed

### Adding shadcn/ui Components

```bash
npx shadcn@latest add [component-name]
```

This automatically adds the component to `src/components/ui/`

### Modifying Styles

- Global styles: [src/index.css](src/index.css) (includes CSS variables)
- Tailwind config: [tailwind.config.ts](tailwind.config.ts)
- Component styles: Use Tailwind utility classes
- Custom CSS variables are defined in `:root` and used via `hsl(var(--variable-name))`

## Important Notes

### Do NOT Modify

- `src/components/ui/*` - shadcn/ui components (only add new ones via CLI)
- Build configuration files unless explicitly requested

### Always Check

- Use TypeScript types for all props and function parameters
- Follow existing component patterns in the codebase
- Use proper semantic HTML
- Ensure accessibility (ARIA labels, keyboard navigation)
- Test components with `npm run test`

### Code Quality

- Run `npm run lint` before committing
- Fix all TypeScript errors before submitting changes
- Keep bundle size minimal (avoid large dependencies)
- Use lazy loading for routes when appropriate

## Development Workflow

1. Start dev server: `npm run dev`
2. Make changes in `src/` directory
3. Test changes: `npm run test`
4. Lint code: `npm run lint`
5. Build for production: `npm run build`
6. Preview build: `npm run preview`

## Design System

This project has a cohesive design system:

- **Spacing:** Use Tailwind spacing scale (4, 6, 8, 12, 16, 24, etc.)
- **Typography:** Clear hierarchy with size classes
- **Colors:** Consistent use of `ot-*` theme colors
- **Animations:** Subtle transitions (fade-in, hover effects)
- **Cards:** Rounded corners with `rounded-card` and `card-hover`

When adding new features, maintain visual consistency with existing components.
